# Atelier v2 設計書

## 1. v1 の診断と v2 の方針

| v1 で「微妙」だった点 | 原因 | v2 の答え |
|---|---|---|
| どの楽器も似た薄い音 | 加算 6 倍音＋フォルマントの汎用シンセに「ピアノらしい値」を入れていた | 物理に基づく**モード共鳴体**（最大 64 モード）＋励起＋胴 |
| モーフの途中が破綻しやすい | 励起の種類がカテゴリ値（pluck/bow…）で、混ぜられない | 励起を**連続量の混合**（打撃量・持続駆動量・息量…）に。全パラメータ連続 |
| 専門家に物足りない | 「専門用語を出さない」を非目標に掲げ、深い編集を隠していた | 段階開示: ブレンド／マップ／発見 → マクロ → 全パラメータ → 変調マトリクス |
| 作ってから弾きに行く | 画面の主役がブレンドの幾何で、演奏が脇役 | 演奏面が常に下にあり、**ループを回しながら彫る**ことができる |
| 持ち出せない | 音はアプリの中だけ | WAV・**SFZ マルチサンプル**・MIDI・共有リンク |

## 2. 音源モデル（`src/engine/synth.ts`）

1 ボイス:

```
励起 ─┬─ 打撃パルス（ハン窓、幅＝基音周期×割合 ← 硬さ）＋衝撃ノイズ ──┐
      ├─ 息ノイズ（持続駆動のエンベロープに追従）──────────────────┤→ モード共鳴体（2 次共振器 × 最大 64）
      └─ 持続駆動: 各モード周波数の正弦（自励振動、ADSR・ざらつき）─→ 直接加算
                                                                    ↓
                                   直接ノイズ層（SVF バンドパス、指数減衰）→ 飽和 → 音量・定位
全ボイスの和 → 胴（3 ピーキング共鳴）→ EQ → コーラス → ディレイ → 生成 IR リバーブ → 幅 → 遅延ゼロのピーク・リミッタ（ワークレット）
```

- **モード比**（`modes.ts`）: 理想弦 / 調律棒（1:4:10）/ 自由棒（cos·cosh=1 の根）/ 理想化調律鐘 / 円形膜（ベッセル零点）。
  表は `modesCompute.ts` の物理式から数値計算して生成し、テストで再計算と照合する。
  「構造」パラメータは隣接ファミリ間を**対数周波数で補間**する。「剛性」は硬い弦の分散 √(1+Bk²) を全ファミリに掛ける。
- **振幅・減衰**: 打点のコム |sin(πkp)|、明るさの傾き r^−α、偶数モード比、T60 = decay × r^−(damping×2.2)。
  離鍵で T60 を「消音（ダンパー）」時間で頭打ち。同じ鍵の打ち直しは共鳴状態を保ったまま再励起（物理的な再打鍵）。
- **硬さ＝接触時間を周期に比例**させた。絶対時間だと高音ほどパルスのスペクトル外に出て弱打が −70dB 以下に落ちる（初版で計測して発見）。
  周期比にすると同じ硬さが全音域で同じ倍音の広がりを作る＝同一音源性。
- **持続駆動**は各モード周波数の再帰正弦発振器。打撃で鳴る共鳴と同じ周波数・減衰・打点を共有するので、擦っても打っても同じ物体に聞こえる
  （鐘の構造で擦ればシンギングボウル、弦の構造で擦ればバイオリン系）。
- **正規化**: 打撃・息・駆動それぞれのモード振幅をエネルギー正規化。高音でモードがナイキストで間引かれても音量が保たれる。

### 実時間の規則
- マスター段は先読みなしのピーク・リミッタ（ワークレット、天井 0.95、解放 120ms）。コンプレッサの先読み遅延を足さない。
  実時間と書き出しで同じノードを使う。
- `process` 経路はアロケーションなし（全バッファ事前確保）。数値破綻したボイスは破棄、出力は NaN/過大値を 0 に。
- モード表は「形状が変わった時だけ」再計算し、音高の変化（ビブラート・ベンド・ゆらぎ）では cos/sin のみ更新。
  発振器は位相を保ったまま状態を変換（振幅も正規化）。
- 再帰フィルタは依存チェーンがレイテンシ律速なので、4 モードずつ並列に処理するカーネルに分けた。
- ボイス・スティールは離鍵済みで最も静かな声 → 最古の順。6ms のフェードでクリックを防ぐ。
- 予約イベントはサンプル精度（区間分割描画）。

### 計測（Node 24 / V8、48kHz、`pnpm bench`）
| 条件 | 1 ブロック (128) あたり | 実時間比 |
|---|---|---|
| 打撃のみ・低音 16 声 × 64 モード | 約 250µs | 約 10% |
| 持続駆動＋息・低音 16 声 | 約 490µs | 約 18% |
| 同上＋ビブラート＋ゆらぎ | 約 530µs | 約 20% |

最初の実装は 50% だった（テーブル引き発振器・毎ブロックの超越関数）。既定の同時発音数は 12。

## 3. パラメータと変調（`src/engine/params.ts`）

- 全パラメータは**正規化値 n∈[0,1]** で補間・変調され、発音直前に物理値へ（尺度: 線形・対数・二乗）。
  だからモーフ・ランダム化・MIDI・変調がどのパラメータにも同じ規則で効く。
- `voice` パラメータ（39）は音ごとに変調マトリクスで評価。`global` パラメータ（胴・FX・LFO、24）はマクロとモッドホイールのみ受ける。
- **つまみの値＝ベロシティ 100・C4 で鳴る音**。変調源はその基準からのずれとして定義:
  ベロシティ (v−0.787)/0.787 ∈ [−1, 0.27]、音高 (note−60)/48、押し込み 0..1、スライド −1..1、ランダム −1..1、Mod エンベ 0..1、LFO −1..1、マクロ 0..1。
  変調量は正規化空間での加算（−1..1）。

## 4. 楽器データ `.atelier`（`src/engine/instrument.ts`）

```jsonc
{
  "format": "atelier.instrument", "version": 2, "id": "…",
  "meta": { "name": "…", "category": "plucked", "tags": [], "description": "…",
            "createdAt": "…", "lineage": [{ "id": "seed:koto", "name": "箏", "weight": 0.5 }] },
  "params": { "structure": 0, "hardness": 0.75, "decay": 4, "bodyF1": 250, … },   // 物理値
  "mods":   [{ "source": "velocity", "target": "hardness", "amount": 0.35 }, …],  // 対応づけ
  "macros": [{ "name": "爪の硬さ", "value": 0 }, …],                              // 8 本
  "play":   { "polyphony": 12, "mono": false, "legato": true, "glide": 0, "bendRange": 2,
              "low": 43, "high": 91, "surface": "strum" },
  "tuning": { "name": "…", "steps": [cents…], "rootNote": 60, "a4": 440 }          // 任意
}
```

読み込みは `sanitize()` が未知キーを捨て、欠損を既定で埋め、値を範囲へ収める。別形式は拒否。
**ブレンド**は全パラメータを正規化空間で重み付き平均、変調は (源,先) ごとに重み付き和、マクロ名・演奏設定は最大重みの楽器から。系譜に重みを記録。

## 5. 領域と同一音源性（`src/engine/descriptors.ts`）

合成コアと同じ式から、音を描画せずにエネルギー分布を見積もる（1 回 ≈0.05ms）:
明るさ（スペクトル重心の対数）・持続（エネルギー加重の実効 T60）・ノイズ感・非調和性・立ち上がり。

- **領域** = 音域 7 点 × ベロシティ 4 段の記述子の網目。マップ上で「この楽器が演奏で辿れる音色の面」として描く。
- **同一音源性スコア** = 網目の各行（ベロシティ一定で音高を動かす）の二階差分（折れ）の平均と最大から算出。
  単調な変化（高音ほど明るい）は罰せず、ある音域だけ別の楽器になる「段差」を罰する。全種楽器 0.75 以上をテストで保証。

## 6. 検証

- `pnpm test`: モード表と物理式の一致、既知値（自由棒 2.756、膜 1.593）、全種楽器の有限性と発音、離鍵後のボイス解放、
  スティール、サンプル精度、データ往復、壊れた入力の整形、ブレンド端点、音律（19 平均律、ミーントーンの純正長三度、Scala）、
  CRC32 既知値、ZIP 構造、WAV、MIDI 往復、共有リンク往復。
- `scripts/smoke.mjs`（ヘッドレス Chromium）: 起動・発音（アナライザ RMS）・ブレンド操作・全タブ・全 29 種の発音・
  弦のストラム・ループ録音（手を離しても鳴り続け、停止で無音）・アルペジオ（押さえた 3 音が順に鳴る）・
  ライブラリ保存 → 再読み込み後も残る → 読み込み → 削除・マルチサンプル ZIP・共有リンクを別ページで開く・
  モバイル幅で横スクロールなし・コンソールエラー 0。遅延（ヘッドレス計測）: baseLatency 10.7ms ＋ outputLatency 16ms。
- `scripts/smoke-xb.mjs`: Firefox で起動・発音・デモ WAV 書き出しを確認。WebKit（Safari 系）はこの環境に必要なシステム
  ライブラリがなく未検証。
- `scripts/render-browser.mjs`: 実際の書き出し経路で全種＋交配 5 例のデモ WAV を描画し、ピーク・RMS・クリップを計測
  （全 34 本クリップ 0、リミッタが働くのは最大でも全サンプルの 0.017%）。

## 7. 既知の限界と次の一手

- 耳での最終調整はまだ（数値検査のみ）。各種のパラメータは物理的な根拠と計測で決めたが、試聴で磨く余地がある。
- ピアノの複弦（2〜3 本の弦のうなりと二段減衰）は未実装。「モードの揺らぎ」で近似している。
- 擦弦・管の持続駆動は「モード周波数の正弦」で、弓と弦の非線形な摩擦（ヘルムホルツ運動）までは模していない。
  将来 `synth.ts` に導波管の励起器を足す余地がある（パラメータ・レジストリに追加するだけで UI・変調・保存に自動で乗る）。
- SFZ は 12 平均律前提。他の音律では 1 半音おきの書き出しを推奨（各鍵を実音律で録音）。
- PWA（オフライン）化、AU/VST などプラグイン化、クラウド共有はスコープ外。
